# Adding Help Content

This guide explains how to author and test help for CLI commands and PowerShell cmdlets in Cirrus.

CLI help and PowerShell help are authored separately, in different folders, with different formats:

| Surface    | Source                              | Format                                      | Tool                            |
| ---------- | ----------------------------------- | ------------------------------------------- | ------------------------------- |
| CLI        | `src/CLI/Help/<group>/<command>.md` | Cirrus markdown (frontmatter + bash fences) | `Cirrus.Help.Tool` (validators) |
| PowerShell | `src/PS/<Module>/help/<Cmdlet>.md`  | PlatyPS schema 2.0.0                        | `platyPS` 0.14.2                |

Both surfaces are validated and built by:

```powershell
.\build\build.ps1 -GenerateHelpArtifacts
```

## Quick Start — CLI

1. **Scaffold templates** for an extension's CLI commands:

    ```powershell
    dotnet run --project tools/Help/Cirrus.Help.Tool -- --scaffold compute
    ```

    This walks `IExtensionIndex.GetCommandTable(ClientType.CLI)` and emits one `.md` stub per command into `src/CLI/Help/compute/`. Existing files are left untouched (idempotent).

2. **Fill in `summary`, `Description`, and at least one bash example.** Required parameters are pre-inlined into the example as `--<name> <type>` placeholders — replace with realistic values or keep as documented placeholders.

3. **Validate:**

    ```powershell
    .\build\build.ps1 -GenerateHelpArtifacts
    dotnet .\artifacts\Debug\Core.Cli\azv2.dll <group> <command> --help
    ```

## Quick Start — PowerShell

1. **Scaffold per-cmdlet markdown** with PlatyPS:

    ```powershell
    .\build\New-PSHelpMarkdown.ps1 -Module Compute
    ```

    This imports `Microsoft.Azure.Cirrus.Cmdlets.Compute.dll` in a child pwsh process and runs `New-MarkdownHelp` against every exported cmdlet, writing to `src/PS/Compute/help/`. Existing files are not overwritten.

2. **Hand-fill** SYNOPSIS, DESCRIPTION, and EXAMPLES. PlatyPS leaves `{{ Fill in the Synopsis }}` placeholders — replace them.

3. **Validate + generate MAML:**

    ```powershell
    .\build\build.ps1 -GenerateHelpArtifacts
    Import-Module .\artifacts\Debug\PS\Compute\Compute.psd1 -Force
    Get-Help New-VM -Full
    ```

## File Structure

```
src/CLI/Help/                  # CLI markdown — Cirrus format
├── compute/
│   ├── index.md               # azv2 vm --help
│   ├── create.md              # azv2 vm create --help
│   ├── list.md
│   ├── show.md
│   └── delete.md
├── config/, login/, resources/, extension/

src/PS/                        # PowerShell — PlatyPS format
├── Compute/
│   ├── help/                  # Author here
│   │   ├── New-VM.md
│   │   ├── Get-VM.md
│   │   └── ...
│   └── en-US/                 # Generated by build.ps1 — do not hand-edit
│       └── Microsoft.Azure.Cirrus.Cmdlets.Compute.dll-Help.xml
├── Config/, Login/, Resources/
```

The CLI `<group>` folder name matches the first CLI token (`vm`, `group`, `login`, `config`, `extension`), **not** the extension name. The mapping lives in `tools/Help/Cirrus.Help.Tool/Program.cs` (`cliGroupByExtension`).

## CLI Markdown Format

Every CLI help file opens with YAML frontmatter, then a `Description:` paragraph, then one or more example sections:

````markdown
---
summary: Create a virtual machine and its networking stack in a single call.
status: ga
schema: 1.0.0
online version:
---

Description: Provisions the full networking + VM stack as a single
operation. Creates a virtual network, network security group, network
interface, and virtual machine using the supplied names and parameters.

### Create a VM with its networking stack

```bash
azv2 vm create --name myvm --location eastus --resource-group myrg --subscription-id 00000000-0000-0000-0000-000000000000
```
````

**Frontmatter fields:**

| Field             | Required | Notes                                                   |
| ----------------- | -------- | ------------------------------------------------------- |
| `summary:`        | yes      | Max ~80 chars. Used in command listings.                |
| `status:`         | no       | `ga` (default), `preview`, `deprecated`, or `internal`. |
| `schema:`         | yes      | Always `1.0.0`.                                         |
| `online version:` | no       | MSLearn URL or empty.                                   |
| `relatedLinks:`   | no       | Flat list of related `azv2 ...` invocations.            |

**Example fences must use `bash` or `sh`.** PowerShell fences are not consumed from CLI markdown — author those in `src/PS/<Module>/help/` instead.

## PowerShell Markdown Format

PowerShell help uses the [PlatyPS schema 2.0.0](https://github.com/PowerShell/platyPS) authoring format. It looks like:

````markdown
---
external help file: Microsoft.Azure.Cirrus.Cmdlets.Compute.dll-Help.xml
Module Name: Compute
online version:
schema: 2.0.0
---

# New-VM

## SYNOPSIS

Create a virtual machine and its networking stack in a single call.

## SYNTAX

```
New-VM -Name <String> -Location <String> -ResourceGroupName <String> -SubscriptionId <Guid> [<CommonParameters>]
```

## DESCRIPTION

Provisions the full networking + VM stack ...

## EXAMPLES

### Example 1: Create a VM

```powershell
New-VM -SubscriptionId 00000000-0000-0000-0000-000000000000 -Name myvm -Location eastus -ResourceGroupName myrg
```

## PARAMETERS

...
````

PlatyPS regenerates the `## SYNTAX` and `## PARAMETERS` blocks from the cmdlet binary on every run, so don't hand-edit them — only `## SYNOPSIS`, `## DESCRIPTION`, and `## EXAMPLES` are author-owned.

## Example Validation

`Cirrus.Help.Tool` validates all examples at build time against the live extension assemblies and cmdlet binaries.

### CLI fences (`bash` / `sh`) — `src/CLI/Help/`

Validation errors when:

- An `azv2 ...` line uses an unregistered group (e.g. `azv2 widget create`).
- The remaining tokens don't resolve to a routed command.
- A `--flag` (or short `-x`) isn't declared on the resolved command and isn't one of the documented globals (`--help`/`-h`, `--debug`, `--output`).
- A flag value doesn't match the declared `ParameterMetadata.Type` or isn't in `AllowedValues`.

### PowerShell fences (`powershell` / `pwsh`) — `src/PS/<Module>/help/`

Validation errors when:

- A `Verb-Noun` doesn't resolve to a registered cmdlet.
- A `-Parameter` isn't declared on the cmdlet, isn't an `[Alias]`, and isn't a common parameter (`-Verbose`, `-ErrorAction`, etc.).

### Conventions

- Use canonical kebab-case for CLI flags (`--subscription-id`, not `--subscriptionId`).
- Both `--flag value` and `--flag=value` are accepted.
- Placeholders pass through unchanged: `<name>`, `<my-rg>`, `$var`, `${var}`, all-zero GUID `00000000-0000-0000-0000-000000000000`.
- Splatted PowerShell commands (`Get-Cirrus @params`) skip parameter validation.

## Runtime Behavior

### CLI Help

`azv2 <group> <command> --help` reads markdown from `<azv2-base>/help/<group>/<command>.md`. The build copies `src/CLI/Help/` → `artifacts/<Config>/Core.Cli/help/` so help works from a local build, and `MarkdownCommandHelpProvider` parses Summary/Description/examples on demand.

### PowerShell Help

`Get-Help <Cmdlet>` reads MAML XML from `<ModuleBase>/<culture>/<dll>-Help.xml`. The build:

1. Runs `New-ExternalHelp` over `src/PS/<Module>/help/*.md` and writes the MAML to `src/PS/<Module>/en-US/<dll>-Help.xml` (committed; PlatyPS-owned).
2. Copies that XML to `artifacts/<Config>/PS/<Module>/en-US/` so `Import-Module artifacts/<Config>/PS/<Module>/<Module>.psd1` resolves help next to the manifest.

## Build Process

### Standard build (no help validation)

```powershell
dotnet build cirrus.slnx
```

### Full help pipeline

```powershell
.\build\build.ps1 -GenerateHelpArtifacts -Configuration Debug
```

This:

1. Builds the solution.
2. Runs `build/Install-BuildDependencies.ps1` (pins `platyPS` to `0.14.2` if missing).
3. Runs `Cirrus.Help.Tool`:
    - `MarkdownStructureValidator` — frontmatter shape.
    - `HelpCompletenessValidator` — every command in `IExtensionIndex` has a markdown file.
    - `ExampleSyntaxValidator` — CLI fences resolve.
    - `PowerShellExampleSyntaxValidator` — PS fences resolve against cmdlet binaries.
    - Emits `artifacts/help/<extension>/HelpManifest.json` and `artifacts/help/HelpIndex.json`.
4. Runs `New-ExternalHelp` per module → `src/PS/<Module>/en-US/<dll>-Help.xml`, then copies into the staged `artifacts/Debug/PS/<Module>/en-US/`.

The build fails non-zero if any validator emits errors.

## Scaffolding New Extensions

```powershell
# CLI markdown stubs from IExtensionIndex
dotnet run --project tools/Help/Cirrus.Help.Tool -- --scaffold <extension>

# PS markdown stubs from cmdlet binary
.\build\New-PSHelpMarkdown.ps1 -Module <Module>
```

Both are idempotent: existing files are skipped. Run them once after adding new commands or cmdlets, then hand-fill the templates.

## Testing Help

```powershell
# CLI surface
.\build\build.ps1 -GenerateHelpArtifacts
dotnet .\artifacts\Debug\Core.Cli\azv2.dll vm --help
dotnet .\artifacts\Debug\Core.Cli\azv2.dll vm create --help

# PowerShell surface
Import-Module .\artifacts\Debug\PS\Compute\Compute.psd1 -Force
Get-Help New-VM -Full
Get-Help Get-VM -Examples

# Automated tests
dotnet test tests/Cli.Tests/Cli.Tests.csproj
dotnet test tools/Help/Cirrus.Help.Tool.Tests/Cirrus.Help.Tool.Tests.csproj
```

## Best Practices

1. **Keep examples concise** — show the command and key arguments, not every flag.
2. **Use realistic placeholders** — all-zero GUID for any subscription/tenant/resource id, `<my-rg>` for free-form names.
3. **One example per task** — "Login with subscription ID", not "All ways to login".
4. **Edit markdown, never code** — no `[Summary]` attributes, no inline help strings in processors.
5. **Run the validators locally** — `.\build\build.ps1 -GenerateHelpArtifacts` runs the same pipeline CI runs.
6. **Don't hand-edit `en-US/*.xml`** — those are PlatyPS output and will be overwritten on the next build.

## Troubleshooting

**`Get-Help` returns empty `REMARKS`:**

- The MAML XML wasn't deployed next to the cmdlet DLL. Run `.\build\build.ps1 -GenerateHelpArtifacts`.
- Confirm the XML landed: `Get-ChildItem artifacts\Debug\PS\<Module>\en-US\`.
- `Remove-Module <Module>` and re-`Import-Module ... -Force` — PowerShell caches the help-not-found result per session.

**CLI help shows no examples:**

- Check that the code fence has a `bash` or `sh` language tag.
- Ensure `### Example Title` precedes the code block.
- Verify the markdown filename matches the canonical command key (`group create` → `create.md` inside `src/CLI/Help/group/`).

**Build fails with `CLI_L1_*` / `CLI_L2_*` / `CLI_L3_*` errors:**

- `L1`: command path doesn't resolve. Cross-check against `ExtensionIndex.cs`.
- `L2`: unknown flag. Check the canonical name (kebab-case).
- `L3`: value doesn't match the declared type. Use a placeholder (`<name>`, `$var`, all-zero GUID).

**Build fails with `PSL1_*` / `PSL2_*` errors:**

- `PSL1`: cmdlet name isn't registered. Check the `Verb-Noun` spelling against the cmdlet class's `[Cmdlet]` attribute.
- `PSL2`: unknown `-Parameter`. The parameter isn't declared on the cmdlet (and isn't an `[Alias]` or a common parameter).

**Build fails locking `Core.Abstractions.dll` or other artifacts:**

- A pwsh session has imported one of the cmdlet modules. Close it (`Remove-Module Compute`, etc.) or exit the pwsh window before rebuilding.

**`platyPS` not found / wrong version:**

- Run `.\build\Install-BuildDependencies.ps1` directly. It pins to `0.14.2`. The build script invokes this automatically; if you bypass it, you may end up with a different version.
